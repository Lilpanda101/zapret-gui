# Zapret GUI для Linux

GTK-оболочка для `nfqws`, `nfqws2` и `tpws` с nftables. Telegram Proxy не используется и не изменяется.

## Движки

- `nfqws2`: настоящий Zapret2 с Lua, профилями, `circular`, hostlist-auto и пресетами Windows Zapret2.
- `nfqws`: прежний резервный режим с шестью встроенными стратегиями.
- `tpws`: только локальный SOCKS5 на `127.0.0.1:1080`, прозрачного перенаправления нет.

Для `nfqws2` требуется системный пакет `zapret2`, предоставляющий `/usr/bin/nfqws2`. Очередь 201 используется отдельно от очереди 200 старого движка.

## Пресеты и редактор

Страница `Zapret2 Lua` содержит 136 штатных пресетов. Она позволяет:

- выбирать пресет и проверять его через `nfqws2 --dry-run`;
- включать и выключать профили через настоящий `--skip`;
- редактировать фильтры и Lua-стратегии профиля;
- импортировать и экспортировать TXT-пресеты;
- анализировать последние ошибки журнала.

Правки сохраняются в `~/.config/zapret-gui/presets`. Одноимённая пользовательская копия имеет приоритет над встроенным файлом, поэтому обновление базы не затирает правки.

Перед боевым запуском адаптер:

1. копирует fakes, lists и Lua в `/etc/zapret/zapret2-runtime/resources`;
2. заменяет Windows-пути на Linux-пути;
3. удаляет `--wf-*` и создаёт входящие/исходящие правила nftables;
4. исключает DNS 53/853 из широких all-port профилей;
5. проверяет пресет через `nfqws2 --dry-run` и правила через `nft -c -f`;
6. только после этого останавливает прежний движок.

WinDivert raw-фильтры не эмулируются. Их основные Discord/STUN-группы переводятся в UDP-порты, а исходные `--wf-*` диапазоны сохраняются. Поэтому пресет проходит проверку ядра, но эффективность каждой стратегии зависит от провайдера.

## Обновления

Кнопка синхронизации загружает из release manifest:

- бинарные fakes;
- списки доменов;
- 136 пресетов;
- Lua-библиотеки;
- WinDivert-фильтры как справочные данные для адаптера.

Каждый файл проверяется по размеру и SHA-256. Запись атомарная. Частичное обновление считается ошибкой, а не успешной синхронизацией.

## Blockcheck2

На странице диагностики доступен системный `/opt/zapret2/blockcheck2.sh` в неинтерактивном режиме. Тест останавливает текущий обход, применяет выбранный DNS и восстанавливает движок даже после ошибки. Лимит 15 минут: при его превышении показывается частичный лог, а не ложное сообщение об успехе.

## Права

Управление выполняется через Polkit с подтверждением администратора. Старое правило `NOPASSWD` для всех пользователей и `/usr/bin/nft` удаляется командой `engine.sh install_polkit`.

Автоматический запуск не меняет BBR и не отключает IPv6. Настройка BBR осталась отдельной кнопкой. Применяется только DNS, выбранный в GUI.

## Зависимости

- **Обязательные:** Python 3.10+, `python-gobject`, `gtk3`, `nftables`, `polkit`, `systemd`.
- **Движки обхода:** `zapret2` (`/usr/bin/nfqws2`), `zapret` (`nfqws`), `tpws`.
- **Опциональные:**
  - `gtksourceview4` — номера строк и расширенный редактор пресетов (при отсутствии используется стандартный `Gtk.TextView`).
  - `libayatana-appindicator` / `libappindicator-gtk3` — отображение иконки в системном трее (при отсутствии приложение работает с панелью задач).
